# AGENTS.md — surge

This document establishes the universal, non-negotiable engineering principles,
communication standards, and operational discipline across Jad Madi's projects.
It serves as the global root of truth for all AI coding assistants (Claude Code,
Devin, OpenCode, Antigravity, Codex, Zed, Cursor, MiMo).

---

## 0. Hard Prohibitions (NEVER Do This)

- **Zero GitHub Workflows / CI Sprawl**: NEVER create or keep `.github/workflows/`
  yaml files (e.g. `e2e.yml`, `ci.yml`, `scan.yml`). All builds, lints, unit tests, and
  E2E suites MUST be executed and verified locally before pushing.
- **No unapproved package managers**: NEVER use `npm` or `yarn`. Use `aube` toolchain
  when present, or `pnpm`.
- **No unprompted remote push or deploy**: NEVER push to remote branches or run deploy
  scripts without explicit user instruction. Local commits are autonomous; remote
  actions require consent.
- **No unauthorized repository creation or namespace re-homing (Provenance & Isnad Guard)**:
  NEVER create new remote repositories (`gh repo create`) or publish external, organizational,
  or community projects/standards under a personal namespace (e.g. `jadmadi/<repo>`). When
  encountering remote authentication failures (HTTP 403) or empty upstream repositories,
  agents MUST fail closed, preserve local commits in the workspace, and report the boundary
  constraint to the user. NEVER circumvent upstream access barriers by creating unauthorized
  personal mirrors or claiming ownership.
- **No Python or Bash automation scripts**: All helper utilities, sync jobs, and CLI
  tools MUST be written in Go.
- **No CGO dependencies**: Pure-Go SQLite (`modernc.org/sqlite`) with `CGO_ENABLED=0` only.
- **No physical directional CSS**: NEVER use `ml-*`, `mr-*`, `pl-*`, `pr-*`, `left-*`,
  `right-*` without LTR container isolation. Use logical properties (`ms-*`, `ps-*`).
- **No Eastern Arabic-Indic numerals**: NEVER use `٠-٩` in UI. Always use `0-9`.
- **No unauthorized copyleft dependencies**: Strictly ban importing third-party GPL, AGPL, or SSPL dependencies unless explicitly authorized with a documented commercial relicensing grant or CLA.
- **Zero silent telemetry or ambient beacons**: NEVER introduce periodic phone-home beacons, unconsented analytics pings, or background network calls. Core Sila is 100% local-first SQLite (`sila.db`). Network interactions must be explicit and user-consented (`--issue`, `--github`, `sila cloud pull`). Cloudflare D1 is strictly an optional edge extension.
- **Zero unredacted outbound payloads**: Outbound data (such as GitHub Issues or Cloudflare Edge submissions) MUST be sanitized to scrub local filesystem paths (`/home/<user>/...`), usernames, and credentials before transmission.
- **No hardcoded secrets or sensitive logging**: NEVER commit credentials or log tokens,
  passwords, payment payloads (CliQ, Stripe), or customer PII.
- **No orphaned or sticky goals**: NEVER implement a goal under `goals/<slug>/` without
  appending the exact attribution path `(goals/<slug>/goal.md)` (or `Goal: <slug>`) to your
  commit message, and NEVER conclude a session without running `sila goals` to confirm it
  transitioned from 🟡 Pending to 🟢 Implemented.
- **No speculative complexity or anti-patterns**: NEVER build unrequested meta-frameworks,
  background daemons, auxiliary subsystems, or complicated abstractions. Take the shortest,
  simplest path to the user's goal. If a change cannot be explained in two plain sentences,
  reject it.
- **No rushed or crude implementations (Zero Corner-Cutting)**: NEVER rush an
  implementation. NEVER close a goal, commit code, or declare a task "done" with a
  crude, shallow, stubbed, or superficial implementation that cuts corners on
  reference screenshots, design specs, uploaded diagrams, or architectural requirements.
  Passing a unit test on a trivial stub does NOT equal a completed goal.
- **No sycophancy or conversational filler**: NEVER open with "You're absolutely right!",
  do not use em dashes, state facts directly.

## 1. Working Relationship & Communication

- **Simplified, concise, and terse**: Keep all communication straight to the point.
  Avoid conversational filler, excessive summaries, or boilerplate restatements.
- **Serve the mission, not the ego**: If a proposed direction is flawed or suboptimal,
  push back constructively with reasoned arguments and verifiable evidence.
- **Evidence over confidence**: Present verifiable evidence (callers, type contracts,
  tests, schemas, benchmarks) rather than model confidence percentages.
- **Two-correction circuit breaker**: If an approach fails twice consecutively, stop.
  Summarize blockers, state what was learned, and propose a clean reset.
- **Language of communication**: Always respond in English, even if the project or
  documentation is in another language.

## 2. Pre-Coding, Scope & Verified Runbook Discipline

- **Verified Repo Runbook Primacy**:
  - Never guess or cycle through package managers, test runners, or build flags.
  - Rely on the project's verified runbook (via `sila prime` or local `AGENTS.md`)
    for exact commands (`go test -race ./...`, `./build.sh`, `aubr test`, `pnpm test`).
  - When introducing a new command, verify exit code `0` on disk before documenting it.
- **Surgical scope**: Touch only what the task requires. Do not reformat adjacent code
  or refactor working code unprompted.
- **Clean up running tasks and processes**: Always terminate and clean up any background
  tasks, dev servers, test runners, headless browser sessions, or child subagents.
- **Deterministic revertibility (temporal hygiene)**: Design exploratory scripts and tests
  to be cleanly revertible. If an operation fails, immediately roll back side effects.
- **Explicit boundary isolation (spatial composability)**: Tools, scripts, and modules
  must declare explicit inputs and produce typed outputs without ambient global state.
- **Strict Reference & Specification Parity (Anti-Rushing Invariant)**:
  - *Honor Human Planning & Reference Depth*: When the user provides reference screenshots,
    visual mockups, category taxonomies, research specs, or architectural designs, the
    implementation MUST faithfully and comprehensively embody every single category,
    field, visual hierarchy, and structural nuance shown. A superficial mock that
    implements only 2 out of 12 categories or leaves hollow structs (`dense.go`,
    `taxonomy.go`) is a catastrophic operational failure that squanders hours of human
    thought, planning, and curation.
  - *Ticking Checkboxes is Not "Done"*: Passing a trivial unit test or marking checkboxes in
    `plan.md` means nothing if the underlying domain logic is a hollow caricature of the
    spec. True completion requires production-grade depth, complete data structures,
    comprehensive edge handling, and genuine business logic.
  - *Pre-Closure Parity Audit*: Before claiming completion or attributing a goal commit,
    the agent MUST perform an explicit Spec & Reference Parity Audit:
    1. Audit every category, field, and visual element present in the reference screenshots/specs
       against the written code.
    2. Verify that all components (taxonomies, scanners, analyzers, rendering logic) are fully
       implemented and robustly tested.
    3. If full, deep implementation exceeds the current turn or context budget, **NEVER fake
       or rush completion**. Stop, explicitly report what is complete versus what remains,
       and propose a clean, sequenced breakdown. Rushing a shallow implementation wastes
       hours of human planning and requires total rewrites.

## 3. Code Architecture & Modular Design

- **Maximize Signal-to-Noise Ratio (Code Economy)**:
  - *Ecosystem over custom*: Search standard libraries and installed packages; delete
    ad-hoc local utilities that duplicate existing tooling.
  - *Harden contracts (Pit of Success)*: Replace loose primitives with strongly typed
    IDs, enums, or discriminated unions.
- **Patterns must pay rent**: Reject mandatory Controller -> Service -> Repository chains.
  Prefer simple direct functions until domain complexity creates a proven boundary.
- **Deep modules over helper shrapnel**: Expose simple domain interfaces that pull
  complexity downward. Avoid shallow micro-helpers scattered across distant files.
- **Happy-path-first & flat control flow**: Use early guard clauses and returns at the
  top; keep the main path linear.
- **Parse, don't validate**: Parse untrusted external data once at the boundary into
  trusted domain types. Internal methods receive trusted types.
- **Make illegal states unrepresentable**: Model domain states using explicit
  discriminated unions (`{ kind: "ready", url } | { kind: "failed", error }`).
- **File size ceiling**: 500 lines soft limit, 750 hard limit. Decompose into focused
  sub-components before crossing it. For large ports, use the three-file triad:
  `<name>.tsx` (UI), `<name>.styles.ts` (Variants), `<name>.types.ts` (Types).
- **"Lean Core" monorepo isolation**: Shared packages (`packages/shared/` or `@shared/*`)
  must remain runtime-agnostic and free of environment-specific globals (`window`, `document`).

## 4. Git & Commit Workflow

- **Always commit locally after every task**: Never accumulate sprawling uncommitted
  diffs. Commit every verified unit of work locally immediately.
- **Deploy on request only**: Never push to remote or run deploy scripts without explicit
  user instruction. Local commits are autonomous; remote actions require consent.
- **Semantic commit messages**: Always use conventional prefixes: `feat:`, `fix:`,
  `refactor:`, `docs:`, `test:`, `chore:`, `perf:`.
- **Closed-Loop Goal Attribution Invariant**: When completing a goal package under `goals/<slug>/`:
  1. Commit with an implementation prefix (`feat:`, `fix:`, `refactor:`, `perf:` — NEVER `docs:` or `chore(goals):`).
  2. Append the exact goal path: `git commit -m "feat(scope): description (goals/<slug>/goal.md)"` (or `Goal: <slug>` in commit body).
  3. Immediately run `sila goals` to auto-reconcile and verify the 🟢 Implemented transition in `goals/README.md`.
  4. **Two-Stage Commit Protocol**: Keep `goals/README.md` strictly separated from feature implementation
     commits. Commit implementation code first, rebuild binary (`./build.sh`), execute `sila goals` to
     synchronize the registry with the new commit SHA, and commit `goals/README.md` in a separate
     `docs(goals): sync goal registry...` commit followed by an immediate `./build.sh` re-compile.
- **Never bypass pre-commit hooks**: Never use `--no-verify`.
- **PR formatting**: Use semantic commit message as PR title; write a 1-3 sentence
  concise explanation of what changed and why. No boilerplate bullet lists.

## 8. Epistemic 4-Pillars Stage-Gate Protocol

Every task follows Sila's seven unskippable stage gates across all harnesses:

1. Orient and Prime (Pillar 1): Run `sila salam` and `sila prime` at session start.
   Use `sila recall "<symptom>"` before web search or workarounds.
2. Charter and Spec Audit (Pillars 2 & 3): Verify `goals/<slug>/goal.md` acceptance
   criteria and spec audit attribution before writing code.
3. Claim and Work Lock (Pillar 2): Acquire atomic lock via
   `sila goals claim <slug> --agent=@<name>`. Respect allowed paths.
4. Implement and Pre-Commit Gate (Pillars 1 & 4): Implement to spec. Run tests
   (`go test -race ./...`) and gate checks (`sila gate check`).
5. Blindfolded Mystery Audit (Pillars 3 & 4): Run `sila hire audit-goal <slug>`
   or `sila goals audit <slug>`. The auditor runs black-box probes in an isolated sandbox.
6. Certify or Remediate:
   - PASS: Verify `audit-receipt.json`, commit with `[goal: <slug>]`, and check `goals/README.md`.
   - FAIL: Inspect `defect-dossier.json`. Remediate under the same slug.
7. Continuity Handoff (Pillar 1): Record directives with `sila memo`, fixes with
   `sila lesson`, and end with `sila handoff` and `sila sync`.

## Sila Trigger Contract

- First command in a repository: `sila salam` prints this loop with live next steps; run `sila --help` to inspect all available tools.
- Task start: run `sila heal` (idempotent; sila's rules, plugin, and MCP entry only, no project git hooks; preview with `--dry-run`), commit refreshed managed files, then `sila prime` and `sila goals ready`.
- Stuck on an error, a package, or an unfamiliar API: run `sila recall "<error or symptom>"` before web search or a workaround.
- Problem solved: record it with `sila lesson "<symptom>" --cause=... --fix=... --files=...`.
- Decision made: record it with `sila memo "<directive>"`.
- Session end: `sila handoff "<summary>" --open="..."` and `sila sync` (or the session-end hook).
- Workspace search (`fffind`, `ffgrep`, ripgrep, rtk) finds code in the current tree; `sila` is cross-harness continuity: past sessions, decisions, and lessons. Use both.
- Sila itself gets in the way or misses something: run `sila feedback "<what happened>" --type=issue|tip|idea` and keep working.
